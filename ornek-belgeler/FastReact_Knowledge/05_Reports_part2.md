### Report configuration

*Context: Main Menu > Reports › Warning › Report configuration*

Reports in FastReact are configured in two stages. The first stage defines the filtering and sorting sequence of data in the report whilst the second stage defines the layout of the report on screen or on the printed page. This section describes the first of these, the content and sequencing of data. For help defining the appearance of the report see Report Layout.

##### Printer and path

This is the configured printer and its network path, if applicable.

##### Printer style

This is default style in which the printer will print the report. This will either be in Portrait or Landscape format.

**Printer configuration (button):** - [Icon: printer settings] Configure the printer.

This button is used to configure the printer settings.

The user can select the printer to which you want to send the report. The currently selected printer is shown next to this button. By default FastReact uses the printer currently set up in Windows.

> **Note:** The selected printer setting is retained until FastReact is restarted at which time it will revert to the Windows default printer.

The user can also select Portrait or Landscape orientation for your report. This setting is retained for this report until you change it.

> **Note:** If the user does not have a printer installed in Windows, FastReact not be able to print any report. However, because the reports generated by FastReact are previewed using the current printer settings (paper size and so on), FastReact will assume 'normal' capabilities and a paper size of A4.

#### General

*Context: Main Menu > Reports › Warning › Report configuration › General*

**Field table:** The grid has the following columns:-

**Column name:** This column contains all data fields that are available in the report. Repeating fields (see Cell options) are expanded to show all of their individual elements. By default these fields are displayed in the sequence that you defined in the selected fields in the report definition stage. However the user can change the sequence by dragging the rows in the grid up or down. The sequence of rows in this table is important only when the user wants to sort the resulting report on more than a single column's data.

**Data type:** This column shows the type of data for each field. Options are T = text with the length in characters, D = date, I = integer value and N = numeric representing a floating point number.

**Sort:** This defines the sort sequence of the report. Click to select ascending, click again for descending and again to return to no sorting. Where the report is to be sorted on multiple columns the sort is performed with columns at the top of the table taking highest precedence

**Subtotal:** You can tell FastReact to insert subtotals at various locations down the length of the report.

> **Note:** This only tells FastReact where to put the subtotals, and not which columns actually require totalling.

For example it would make sense to subtotal production output per week for a line or group, but subtotalling selling price would not be a useful exercise. The user must tell FastReact which columns to subtotal when at the Cell options of the Report Layout stage or else subtotals will not appear on the report.

**Page:** This allows the user to separate the printed report into different pages according to the report content. Page breaks are inserted when the value of the selected column changes. For this reason this option is only valid on a column which is both sorted and subtotalled.

**Exclude:** Normally the filtering of report data (see below) defines that data which will be included in the report. A filter can also be set up so that certain data may be excluded.

**Filter from / Filter to:** In addition to defining the sequence of the report the user can also define its content. Filters can be a simple range filter or the user can use wild cards to select a subset of data in reports.

For example the user could limit the report content to all orders for a specific customer being made in a range of production lines.

The user can also filter using dates but this is limited to selecting a date range; wild cards being inappropriate. The date format required is shown in the Type column of this grid This is defined in the International or Regional setting in the Windows Control Panel.

Fields which can be blank (UDF’s) need a 'from…..' and a 'to…..' filter to prevent the reporting of blanks.

However if, for example, a UDF field is being used to hold numbers and 3 is entered in the 'from…..' filter and the 'to…..' filter is left blank. The report will return all instances where the UDF is greater than or equal to 3.

##### Range filtering

Enter the filter limits in the last two columns in the screen. Filtering will work on text, numeric and date column types.

For example, entering 'ABC' in the first column and 'JFK' in second column will select just those data items whose values lie between (and include) 'ABC' and 'JFK'.

##### Wild card filtering

To select a range of report rows, enter the wild card pattern that you want to match in the first column only. Any value in the second column will be ignored, except in the special case as described below. Wild card filters are described at the end of this section.

##### Combined Range and wild card filtering

Entering the same pattern of literal characters and an '\*' in the filter from and filter to columns, then FastReact will search and report any rows which both match the pattern and lie within the specified range.

For example 'ABC\*' and 'JFK\*' will include any rows which start with 'ABC' through to any rows starting with 'JFK'. Alternatively, '\*ABC' and '\*JFK' will report rows ending with these literal characters.

##### Find filtering

If you enter a value in the 'Filter from' column and leave the 'Filter to' column empty then FastReact will report just those data rows which precisely match the filter value.

> **Note:** In this case wild card characters are not allowed.

The above filter options allow a great deal of flexibility in report content.

##### Wild cards explained

Two wild card match characters are available. An asterisk ‘\*’ and a question mark ‘?’. The asterisk matches any number of characters whilst the question mark matches one single character.

For example:-

##### Entry Matches

ABC\* ABC, ABCD, ABCDEF, ABC7

\*ABC ABC, 7ABC, XYZABC

\*ABC\* ABC, XYZABC, ABCDEF, XYZABCDEF

A\*C ABC, AXC, AXXXXXC

?BC ABC, XBC

A?C ABC, AXC

AB? ABC, ABX

?B? ABC, XBX

The following use of wild cards is not allowed as the results would be unpredictable:-

Entry Comments.

A\*\*B Can not use two wild cards together.

A\*B\*C Can not use two \* unless at beginning and end.

A\*B? Can not use \* and ? in the same entry.

##### Options

**Preview first page only:** When FastReact constructs the reports it generates preview pages so that the user can either view the entire report on screen, or check that the report is correctly formatted before printing by viewing the first page only.

**Skip pages which have no valid data:** If for example, a production output report for a period of days is required and those days extend to pages a, b, c, d, etc but no data appears on pages b, c, and d, then FastReact will not print the pages with no data, saving paper.

For example a production output report between 1 September and 30 November would not report Orders planned in December.

**Suppress zeros:** Any numeric zeros in reports will be shown as a dash '-' rather than a zero. This can make some reports more comprehensible.

**Show subtotals only (Suppress data lines):** This option should be ticked if there is a requirement for summary only reports. In this case only the subtotal values will be shown and not the individual report lines. The report will be empty if there are no defined subtotals.

**Hide subtotal if only one item:** This option will hide the subtotal if there is only one item on the report which is to be subtotalled.

**Grand totals:** Select this option if you want a grand total at the foot of your report. Only columns that have been selected as having a subtotal in the Report Layout will be shown.

##### Include date range

**Date range:** This option only really applies to date based reports.

For example, production output reports where the columns in the report will cover a period in time. Use these fields to define the period that you want the report to cover.

**Skip report lines where no data appears in date range:** If the report is date based and there is no information between the dates specified then FastReact will ignore that line and not report it producing a more concise report.

##### Headers

**Left:** The report can have manually entered header. This option places the header on the left side of the report.

**Centre:** The report can have manually entered header. This option places the header in the centre of the report.

**Right:** The report can have manually entered header. This option places the header on the right side of the report.

##### Configuration

**Save as:** Having configured the report with the content and data sequence required, FastReact will save all the settings for the next time the user runs this report. Settings are individually saved for each report. In addition the user can create a variant of the standard report by entering a name in the box provided. These names should be meaningful in order to make it easier to recall the variant later on.

In this way an Order report could show all orders for all customers whilst a variant of this could show only a single customer and all the orders associated with that customer, without having to reconfigure the report each time.

**Description:** Enter into this field a meaningful description for the report. This will be shown on the top of each report page and in the report selection list.

#### Advanced

*Context: Main Menu > Reports › Warning › Report configuration › Advanced*

The advanced tab offers the user greater flexibility when pulling data from the database and designing the required reports. It also offers the user various export methods as well as automatic scheduling of the reports, depending upon the systems licence and setup.

##### Exception reporting

FastReact can produce exception reports that only include data which lies between a specific numeric range. The user can do this with the filters described above, however, these are only applicable to data fields and not to calculated values.

For example, the user can filter to show only those resources that are loaded above a certain actual value, but cannot filter those that are loaded above a certain % load as this would be derived from a formula linking load against capacity. Using the exception facility you can show just those resources that are, for example, more than 110% loaded.

To define the values for the exception report click the button at the right hand side of the Exception reporting label.

##### Exception values

Define the operator(s) and the value(s) that are required. The user can specify the following operators to use in order to compare the report data value with the value defined:-

none

- <
- <=
- =
- >=
- not equal.

The user can check a single value or check a range. This option allows the user to test values that are within or outside an upper and lower limit. The options are:

- and
- or.

##### Required action

FastReact can take action when it finds values that are within the criteria specified above. It can:-

**Highlight exception values:** This option will force FastReact to highlight the values declared in the Exception values fields, above.

**Show only exception values.:** This option will force FastReact to only show the values declared in the Exception values fields, above.

**Hide rows without exceptions.:** This option will force FastReact to hide the rows that do not match the values declared in the Exception values fields, above. However, the hidden rows will still be included on any subtotal values.

**Exclude rows without exceptions.:** This option will force FastReact to hide the rows that do not match the values declared in the Exception values fields, above. However, the hidden rows will still be excluded on any subtotal values.

**Warning.:** To apply these exception values the option 'Apply exception' in the Layout of the report must be checked for any fields where the exception criteria needs to be applied.

##### Exporting

**All data:** This option will export all of the data on the current report.

**Normalise exported data:** Exported data which contains repeating data (such as weekly schedules) can either be formatted as seen in the report with columns representing each element in the repeating data set, or the data can be normalised. In this case the data which repeats will be exported in its own line in the output file. This format can be easier to manage when importing to another system.

> **Note:** With this option disabled the exported file format will be as set in the Export report Options. However, if it is enabled, then the format of the exported data will be as defined in the Export file format. Both of these settings may be found in Main menu - Setup - Configure - General in the Export tab.

**Warning:** If the user plans to export the report in normalized format then the repeating fields MUST be configured on the Report Designer so that they are at the end of the list. Repeating field which are marked as non-repeating Must also be towards the end of the list.

For example:

- Normal non repeating fields
- Repeating fields (marked as non-repeating)
- Repeating fields.

**As displayed:** This option will export the report data as it is displayed in the FastReact reporting module.

**Save dates in export format:** Normally the format of dates is that which is defined in the Main menu - Setup - Configure - Export tab. This means that exported data is always in the same format irrespective of the Windows locale settings of the workstation performing the export. When the user manually exports data the date format does, however, default to the Windows locale so that the user can more easily interpret these dates. However, FastReact can use the pre-defined format by selecting this option.

##### File format

This is the style/format which the report will be exported in. The default option, which is set up during the configuration of FastReact, can be over ridden on a report by report basis.

**Default:** This is the format as defined when setting up the FastReact system.

**Character Separated Variable text file (CSV):** This format will produce the report in an Excel spreadsheet.

**Tab Separated Variable text file (TXT):** This format will produce the report in a text document.

**Database:** Choosing this option will automatically normalize the data and export it to a nominated database. This database can be nominated during set up, and will therefore be the default export method, or it can be nominated during the previewing of the report when the user opts to save the report. When exporting a table to a database, there is a set criteria that must be followed. This can be found here.

##### Scheduling

These automatic functions provide facilities for generating reports at a specific time of day or on a weekly schedule. However, to prevent several workstations each generating the same reports (if they are left on by mistake) the automatic functions only work for a user called 'Service'. The 'Service' user must have rights to run this report.

##### Options (for Service user only)

**Auto run on timed schedule:** If auto execution of reports is enabled, then selecting this option will include this report in the automatic report run. As the report generator is used to produce export (to another computer system) files, this will allow these files to be produced unattended. If the user selects the option, then a valid file name for the exported file must be entered (do not enter a path as this is defined elsewhere. If the file name is left blank then an error will be raised. If the file name is invalid then the report export will not be executed.

This option must also be selected if the report is to be emailed.

**Auto print report:** In addition to producing export files the user may elect to also send the report to a printer. Please make sure that the printer is attached and is on line.

**Print to ‘remote’ file:** Instead of printing the report to a printer the report may be formatted and sent to a file that can be opened in the FastReact Remote Extension report viewer. This allows reports to be generated that can be e-mailed to recipients (not automatically) and do not rely on a printer being available at the time of the scheduled export.

**Auto E-mail report:** Instead of printing the report to a printer the report may be formatted and sent via email. The person to which the report is being e-mailed MUST be set up within FastReact and have a valid email address.

This drop down menu allows the user to resize the viewed page on screen.

**Page width (button):** - [Icon: Page width] Fit the page to the width of the screen.

This button fits the page width into the screen.

**Full page (button):** - [Icon: Page full] View the full page.

This button fits the whole page onto the screen.

**First page (button):** - [Icon: Return to todays date] Jump to the first page.

This button jumps to the first page in the report.

**Page up (button):** - [Icon: Up Down] Go up a page or Go down a page.

This button will scroll the pages up, page by page.

For example, clicking this button on page 4 will result in page 3 being shown.

Or scroll the pages down, page by page.

For example, clicking this button on page 4 will result in page 5 being shown.

**Page across (left) (button):** - [Icon: Left Right Move] Move back a page or move forward a page.

This button will scroll the pages across, page by page.

For example, clicking this button on page 4b will result in page 4a being shown.

Or scroll the pages across, page by page.

For example, clicking this button on page 4b will result in page 4c being shown.

**Page number (button):** - [Icon: Page number] Select the required page.

The above six buttons are used to negotiate vertically and horizontally around the report. Where a report has more columns than can fit on a single page, the report generator will produce pages 'b', 'c', 'd' and so on. The user can scroll horizontally across these pages. Using the page list box you can jump directly to any page.

**Rebuild (button):** - [Icon: Rebuild report] Rebuild the report.

This button forces the full report to be rebuilt. If 'Preview first page only' is selected and correct thin clicking this button will rebuild and display the entire report.

**Redo (button):** - [Icon: Redo report] Redo the last action.

This button will redo the last action.

**Print (button):** - [Icon: Print report] Print the report.

Clicking the print button will bring up the Page Selection Dialog so that you can make a final page selection if you do not want the whole report printed.

**Abort (button):** - [Icon: Abort report] Abort the current action.

This button will abort the current action.

**Save (button):** - [Icon: Save report] Save the report.

Reports may be exported to a disk file for importing into other software systems or for manipulation of the data in a spreadsheet or word processor.

If the report has been set up to export to a database then another dialog will appear requesting the database table name. This dialog must contain, at the very least, the database name separated by two colons and then the database table name.

For example, database::table.

The database must already exist within the target location but FastReact will automatically create the table within the database.

**E-mail (button):** - [Icon: email report] E-mail the report.

Reports may be emailed for viewing in the FastReact Remote Extension program. The person to whom the report is being emailed MUST be set up as a user within FastReact.

Show first filter on report

Reports can be grouped in batches so that batches of reports can be printed.

**PAD favourites (button):** - [Icon: Repoprt favouites] Add the report to the PAD favourites list.
